# Wireless remotes, scenes and a helper

Scenes and automations both come from directories of YAML files, and the automations refer to
the scenes by the `entity_id` of their `homeassistant_scene` resources, so Tofu creates the
scenes first and an automation never points at a scene that does not exist. The scene files are
trimmed versions of what the scene editor saves: only `state`, `brightness` and color matter
when a scene is applied, and `${e.…}` keys keep entity IDs out of them. An IKEA Styrbar remote is
read straight from Zigbee2MQTT with `mqtt` triggers, generated by a `%{ for }` loop over its
button payloads, and switches between the scenes. An Aqara wireless switch outside the child's
room uses a blueprint (`use_blueprint`) and sets an `homeassistant_input_boolean` "light lock",
which a second automation enforces and resets every morning. The blueprint has to be in Home
Assistant already; the provider does not manage blueprints.
